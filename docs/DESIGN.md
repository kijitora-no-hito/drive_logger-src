# ドライブロガー 設計メモ（docs/DESIGN.md）

自動車用の GPS ロガー＋ドラレコ風の GPS カメラ。**ナビ機能は作らない。**
流用元: 自転車ルートロガー（`../cycle_route_logger`。記録・統計・GPX・更新の確認・Maps キー・署名）、
GPS カメラ（`../gps_camera`。カメラ全面＋HUD・方位・地図の小窓）。元のアプリは変更しない。

## 1. 基本

| 項目 | 値 |
| --- | --- |
| アプリ名 | ドライブロガー |
| applicationId / namespace / パッケージ | `jp.kjtr.drivelogger`（公開後は変えられない） |
| 版 | versionCode 9 / versionName 0.8.0（0.7.0 = 8、0.6.0 = 7、0.5.0 = 6、0.4.1 = 5、0.4.0 = 4、0.3.0 = 3、0.2.0 = 2、0.1.0 = 1。0.8.0 は徒歩で融合をやめる・Google の融合測位・獲得標高・比較表示・軌跡のなめらかさ・乗り物・Room 版 6（§4.7・§4.8・§3.5）。0.7.0 は長時間録画・Room 版 5（§3.11）。0.6.0 はドライブ＝GPS ログ・動画ログの入れ物・Room 版 4（§4.6）。0.5.0 はホーム画面の追加（§7）） |
| SDK | minSdk 24 / compileSdk 36 / targetSdk 36（edge-to-edge 強制。録画 ON の間だけ横向きに固定（設定「録画の向き」。§3.10）。それ以外は固定しない） |
| 配布 | GitHub（`kijitora-no-hito/android-apps`、タグ `drivelogger-v<版>`、releases.json の folder `drive_logger`） |

## 2. 全体の構成

```
DriveApp（アプリに 1 つずつ）
 ├─ LocationHub        端末の位置（LocationManager。acquire/release の参照カウント）
 ├─ DriveSession       GPS 記録 1 本の進行（DriveTracker で統計。点を Room に逐次保存）
 ├─ DashcamEngine      CameraX（Preview + VideoCapture + OverlayEffect）とループ録画
 │    ├─ ClipStore     録画ファイルと clip 表（容量の管理・保護・削除）
 │    └─ BurnIn        焼き込みの文字（BurnInText＝純ロジック、BurnInRenderer＝Canvas）
 ├─ PhotoRepository    写真（フォトライブラリ・photo 表・EXIF・縮小版。0.4.0〜 §3.9）
 ├─ PhotoShooter       写真を撮る窓口（録画中は ImageCapture / プレビューのフレーム。駐車中は 1 回の測位）
 ├─ SnsExporter        SNS 用・ギャラリー向けの書き出し（Media3 Transformer。覆い / あとから重ねる表示 §3.10）
 ├─ ImpactMonitor      加速度センサー → ImpactDetector（純ロジック）→ 保護
 ├─ RecorderStatus     サービスの様子（画面が読む）
 └─ UpdateManager      更新の確認

DriveService（FGS。type = camera | location | microphone（音声 ON のときだけ））
 └─ 走行中ずっと動く。位置の取り込み・録画の分割・衝撃の監視・通知・熱・カメラ喪失の扱い。
```

- **0.6.0〜 ドライブは GPS ログ・動画ログの入れ物**（§4.6）。ドライブを開く＝記録の開始ではない。開いている間に GPS ログ・動画ログをそれぞれ何本でも記録でき、
  閉じたドライブも再開して記録を足せる。以下の 0.5.0 までの説明の「走行」「記録」は、0.6.0 では「GPS ログ」と読み替える。
- （0.5.0 まで）走行（ドライブ）＝［開始］〜［終了］＝ドライブ 1 本。**基本は GPS の記録だけ**（カメラを使わない。電池・発熱・容量に優しい）。
  **録画はオプション**（2026-10-13 ユーザー要望「毎回必ずではなく、オプション的に」）:
  - 開始前に大きな 2 択［記録だけ］［記録＋録画（ドラレコ）］。初期値は前回の選択（設定の「開始時の既定」で 前回 / 記録だけ / 記録＋録画）。
  - 記録中にあとから［録画 ON］/［録画 OFF］できる。ON でカメラの画面（ドラレコ風）に切り替わりループ録画が始まる。
    OFF で録画を止めて地図の画面に戻る。**GPS 記録は途切れない。**
  - 録画 ON はアプリが前面のときだけ（Android 14+ は camera / microphone 型の FGS を裏から足せない）。裏では切り替えない。
  - 録画していた時間帯はドライブの出来事 `video`（開始〜終了）に残し、動画（clip）はその時のドライブに紐づく。
- 画面の構成: ホーム（起動時の画面。0.5.0〜。開始の 2 択・最近のドライブ・入口。§7）／走行画面（ドライブ中だけ。記録だけ＝地図＋大きな速度の HUD、録画中＝カメラ全面＋HUD＋地図の小窓）／
  ドライブの一覧・詳細／動画の一覧・再生／設定。

## 3. 録画（dashcam/）

### 3.1 カメラの結び方

- `DashcamEngine` は自前の `LifecycleOwner`（`EngineLifecycle`）にカメラを結ぶ。**録画 ON の間だけ** STARTED にし、
  OFF で DESTROYED にしてカメラを閉じる（記録だけのときはカメラを一切開かない）。アクティビティやサービスのライフサイクルに
  直接結ばないのは、画面が裏に回ってもカメラを途切れさせないため。
- 録画 ON で **UseCaseGroup(Preview, VideoCapture, ImageCapture（0.4.0〜。録画中の写真 §3.9）, OverlayEffect（焼き込み方式のときだけ §3.10））** を 1 回で結ぶ
  （効果は同じ bind で渡さないと効かないため）。結べなければ ImageCapture → 効果 → 60fps の順に外して結び直す。
- 画面が見えている間だけ `Preview.setSurfaceProvider(previewView.surfaceProvider)`。画面が隠れたら `setSurfaceProvider(null)`。
  録画（VideoCapture）はそのまま続く。切り替えでカメラのセッションが組み直されるので、**その瞬間に動画のフレームが少し止まることがある**
  （エミュレータでの確認結果は CLAUDE.md）。
- PreviewView は `COMPATIBLE`（TextureView）。地図（SurfaceView）との重ね順を素直にするため（gps_camera と同じ）。
- 画面の向き（0.4.0〜）: 設定「録画の向き」横（既定）なら、録画 ON の間は画面を `SENSOR_LANDSCAPE` に固定し、VideoCapture / ImageCapture の
  `targetRotation` は画面がまだ縦でも横（ROTATION_90、画面が横ならその向き）にする。録り始めて 8 秒以内に画面が逆の横向き（ROTATION_270）に
  決まったら、上下逆の動画にならないよう今のファイルを切り替える。「端末の向きに従う」なら今までどおり、画面の回転を**次のファイルから**反映する。

### 3.2 ループ録画（分割）

- `Recorder` は同時に 1 本しか録れない。分割は「今の Recording を `stop()` → すぐ次の `PendingRecording.start()`」。
  Recorder は前のファイルの仕上げ（finalize）中に始めた録画を「保留」として持ち、仕上がり次第すぐ始めるので、
  2 本を重ねずに途切れを最小にできる（目安 0.1〜0.5 秒。端末次第。エミュレータの実測は CLAUDE.md）。
  `setDurationLimitMillis` は使わない（上限で止まった後に次を始めるので途切れが長くなる）。
- 分割の長さ: 1 / 3 / 5 分（既定 3 分）。タイマーで切る。各ファイルの開始時刻は `VideoRecordEvent.Start` を受けた時刻（壁時計）。
- 保存先: `getExternalFilesDir(DIRECTORY_MOVIES)/dashcam/`（アプリ専用の外部領域。ギャラリーには出ない。`.nomedia` も置く）。
  ファイル名 `DL_yyyyMMdd_HHmmss.mp4`。アンインストールで消える（大事なものは［ギャラリーに書き出す］）。
- ビットレートは固定で指定する（容量の見積もりを安定させるため）: 720p 6 Mbps / 1080p 12 Mbps / 4K 35 Mbps、60fps は 1.5 倍。
- 録画の失敗（`Finalize` のエラー）: 中身があるファイルは残す（`ERROR_SOURCE_INACTIVE` など）。走行中なら 3 秒おいて次を始め直す。
  `ERROR_INSUFFICIENT_STORAGE` は録画を止め、通知と出来事に残す。

### 3.3 HUD の焼き込み（OverlayEffect）

- `androidx.camera:camera-effects` の `OverlayEffect(VIDEO_CAPTURE)`。**プレビューには掛けない**（画面は Compose の HUD を出す。
  焼き込みの見た目は設定の「見本」で確かめる）。Google マップは焼き込まない（規約。画面だけ）。焼き込む地図は地理院タイル（§3.7）。
- 毎フレーム `onDrawListener` で overlay の Canvas を消してから描く。Canvas はバッファの座標（センサーの向き）なので、
  `frame.rotationDegrees` から「正立の座標 → バッファの座標」の変換（`BurnInLayout.uprightToBuffer`、純ロジック）を掛けて描く。
- 焼き込む項目（設定で選ぶ）: 日時（秒まで）・速度 km/h・緯度経度・方位（8 方位＋度）・G（任意・既定 OFF）・アプリ名の小さな表記。
  位置（左下・右下・左上・右上。既定 左下）・大きさ（小・中・大。短い辺に対する割合）。白い文字に黒い縁取り。
- 文字の組み立ては `BurnInText.lines()`（純ロジック・単体テスト）。描画は `BurnInRenderer`（同じ Canvas の処理を設定の見本でも使う）。
- 描く値は `BurnInState`（AtomicReference）。メインスレッドが位置・G のたびに更新し、効果のスレッドが読む。
  速度は直近 5 秒以内の測位だけ（古ければ `-- km/h`）。方位は動いている（10 km/h 超）ときの進行方向、止まると最後の値。
- OverlayEffect を作れない・結べない端末では、焼き込み無しで結び直して録画を続ける（RecorderStatus.burnInUnavailable）。
- 表し方（2026-10-13 追加要望「スピードなどをメーターで表示するオプション」）: 文字 / メーター（既定 文字）。メーターのときは
  速度・方位・G の項目がそれぞれ速度計・コンパス・G メーターになり（文字 2.2 行分の半径。コンパス・G はその 0.62 倍）、残りの文字（日時・緯度経度・アプリ名）の上に並ぶ。
  走行画面の HUD も別に 文字 / メーター を選べる（例: 画面はメーター、動画は文字）。§3.8。
- 配置の計算（0.3.0〜）: `BurnGeometry`（純ロジック）が文字の各行・メーター・地図の位置を決め、描画（`BurnInRenderer`）も同じ結果で描く。
  速度と方位は**幅の決まった枠**（速度 `888 km/h`、方位 `NW 359°` の幅。等幅の文字）に入れて描くので、速度の場所は値によらず一定。
  録画したファイルを仕上げるとき、その配置（速度の文字の矩形 / 速度計の円・緯度経度の矩形・地図の窓、正立の px）を clip 表の
  `burnLayout`（JSON の `BurnLayout`）に保存する。SNS 用の書き出しで覆う場所に使う（§5.1）。

### 3.7 地図の焼き込み（map/。2026-10-13 追加要望「動画に地図も焼き込むオプション」）

- 地図は**国土地理院の地理院タイル**（`https://cyberjapandata.gsi.go.jp/xyz/{std|pale|seamlessphoto}/{z}/{x}/{y}.png|jpg`）。
  国土地理院コンテンツ利用規約により出典を表示すれば動画への利用も可 → 地図の窓の下に「出典：国土地理院（地理院タイル）」を焼き込む（外せない）。
- 設定（既定 OFF）: 大きさ 小/中/大（短い辺の 28/36/46%）・位置 4 隅（既定 右下。文字と同じ隅なら積む `BurnInLayout.mapOrigin`）・
  ズーム 13〜17（既定 15）・向き 進行方向が上（既定）/北が上・種類 標準/淡色/写真・軌跡 なし/直近 1 km/直近 5 km（既定）/全体（`TrackTail`）。
- 描画（`MapBurnRenderer`、OverlayEffect のスレッド）: タイル＋軌跡を窓と同じ大きさの合成画像に描いておき、毎フレームはそれを
  BitmapShader で角丸に 1 枚描く＋現在地の矢印・北の印・出典・枠。合成画像は位置 1 px / 向き 1° 以上の変化で 100 ms、タイルの到着・軌跡の変化で 500 ms 以上あけて作り直す。
  タイルは窓の一辺 / 300 倍（0.75〜2.5）で描く（解像度が違っても同じくらいの範囲）。取れていないタイルは灰色、位置が分からなければ最後の位置（無ければ灰色の窓）。
- 取得とキャッシュ（`GsiTileStore`）: 描く側は `tile()` でメモリ（RGB_565・16 MB の LRU）から読むだけ。無ければ null を返し、裏の 2 本のスレッドが
  ディスク（`cacheDir/gsi_tiles/<種類>/<z>/<x>/<y>`）→ 通信の順に読む。通信は地図の焼き込みが ON・ネットワークありのときだけ。
  User-Agent はアプリ名と版。取得から 30 日は取り直さない（404 は 0 バイトの印）。失敗は 60 秒あけ、3 回続けて失敗したら 30 秒休む。
  上限 200 MB を超えたら取得の古い順に 90% まで消す（`TileCachePolicy`）。設定に使用量と［キャッシュを削除］。
- 先読み（`TilePrefetch`、走行サービスの 4 回/秒の更新から。録画中・焼き込みが効いているときだけ）: 表示範囲の外接円＋半タイル、
  10 km/h 以上なら進む向きに表示範囲 1 つ分先の円。1 回 40 枚まで、中心のタイル・45° 単位の向き・動いているかが変わったか 15 秒たったときだけ計画し直す。
  まだ始めていない古い場所の先読みは捨てる。
- 設定の見本も同じ描画で地図を出す（現在地、無ければ東京駅）。

### 3.8 メーター（gauge/）

- `GaugeRenderer`（android.graphics.Canvas に描く。大きさはすべて半径に比例）を、画面（Compose の `drawIntoCanvas`）と焼き込み（OverlayEffect）で共用する。
  角度などは `GaugeMath`（純ロジック）。
- 速度計: 7 時半〜4 時半の 270°、上限 120/180/240 km/h（設定・共通。既定 180）。目盛り 10（240 は 20）、数字 20（240 は 40）ごと。中に数字。
- コンパス: 文字盤が回り、進む向きが上（上の印）。中に度。
- G メーター: 外の円 0.6 G（円 0.2 G ごと）。点は体が押される向き（ブレーキ → 上、加速 → 下、右に曲がる → 左）。
  `VehicleGEstimator`（純ロジック）: GPS の 2 点の間の加速度の平均を、前後とも止まっていたら重力として強く取り込み（走行中はごくゆっくり）、
  GPS の速度の変化（前後）と方位の変化 × 速度（左右）を、その間の端末の水平の加速度と掛けて足し合わせて車の前・右を求める。
  手がかりが足りないうちは水平の G の大きさだけ（円の大きさで表す）。加速度センサーは衝撃の監視（`ImpactMonitor`）と同じものを使う（走行中だけ）。
- 走行画面: メーターのとき左上に速度計（縦 130dp / 横 150dp）と、その右にコンパス・G メーター（設定で出す/出さない）。

### 3.9 写真（photo/・ui/CameraScreen・ui/PhotoUi。0.4.0〜、2026-10-13 ユーザー要望「自転車版と同様に写真を撮影して残せるように。一つのドライブ記録中に部分的に録画したり、写真を撮ったり。柔軟に」）

自転車ルートロガー（0.3.0 の写真）と同じ作り。**どの状態でも撮れる**:

| 状態 | 撮り方 | photo.captureMode |
| --- | --- | --- |
| 録画中（記録中） | 走行画面の［写真］。**録画を止めずに**、走行画面のプレビューのまま撮る（カメラ画面は開かない＝録画のカメラとぶつからない） | `still`（ImageCapture）/ `frame`（代わりの方法） |
| 記録だけ | 走行画面の［写真］→ アプリ内カメラ画面（CameraX Preview＋ImageCapture、連写可） | `camera` |
| 駐車中 | 駐車中の画面の［写真を撮る］→ アプリ内カメラ画面（§4.4） | `camera` |
| 記録していない | 走行画面のメニュー［写真を撮る（カメラ）］（ドライブに紐づかない写真） | `camera`（tripId なし） |

- **録画中の撮影の仕組み**（`PhotoShooter.shootWhileRecording`・`DashcamEngine.takeStill / grabPreviewFrame`）:
  1. 既定: 録画の UseCaseGroup に **ImageCapture も一緒に結ぶ**（Preview＋VideoCapture＋ImageCapture、焼き込み方式なら＋OverlayEffect(VIDEO_CAPTURE)）。
     ［写真］で `ImageCapture.takePicture`（MINIMIZE_LATENCY）。静止画の要求は録画の流れと並んで処理されるので、**録画は止まらない・ファイルは切れない**
     （エミュレータ: 1 分のファイルの途中で 2 枚撮って、ファイルは 57.8 秒・1 本のまま。`DL-Dashcam: bound: effect=true still=true`）。
     焼き込みは VIDEO_CAPTURE にだけ掛かるので、写真は**素の写真**（既定）。
  2. 3 つ同時に結べない端末・組み合わせ（`bindToLifecycle` が例外。LEGACY の端末など）: ImageCapture を外して結び直し（`PhotoMode.FRAME`）、
     ［写真］では**走行画面のプレビュー（PreviewView.getBitmap）＝焼き込みの手前の映像の、画面に見えている範囲**を写真にする（画面の解像度。
     FILL_CENTER なので端が少し切れる）。debug だけ `--ez photoFallback true` で試せる（エミュレータで 2400×1080 の写真になった）。
     どちらで撮ったかは写真の行（`captureMode`）と拡大表示の 2 行目に出す。
  3. 設定「録画中に撮った写真にも焼き込みを入れる」（既定 OFF）: 撮った画像（ImageCapture は一度アプリの cache に書いてから読む）に、
     押した瞬間の値・今の焼き込みの設定で `BurnInRenderer.drawUpright` を描いてからフォトライブラリに保存する（地図の焼き込みも同じタイル）。
- 撮ったら走行画面の写真のボタンの上に小さく「撮りました」を 2 秒（大きな知らせ・音は出さない）。**シャッター音は端末の決まりに従う**:
  Android 13 以上は `MediaActionSound.mustPlayShutterSound()` が true（日本の端末など）のときだけ鳴らす。12 以下は調べられないので鳴らす（CameraX は自分では鳴らさない）。
  写真のボタンの下に「運転中は操作しない」、カメラ画面の上にも同じ注意。
- 保存（`PhotoRepository`）: MediaStore `Pictures/ドライブロガー/DL_yyyyMMdd_HHmmss_SSS.jpg`。EXIF に撮影日時（DateTimeOriginal・SubSec・OffsetTime）と、
  設定「撮った写真に位置（GPS）を書き込む」（既定 ON）なら GPS。位置: 記録の最後の点（10 秒以内）→ 端末の測位（30 秒以内・精度 50 m 以内）→
  軌跡から時刻で補間（`PhotoLocator.interpolate`。端から 5 分・点の間が 10 分以上空いていれば補間しない）。駐車中は撮るたびに 1 回測位（§4.4）。
  縮小版（長辺 320 px）を `files/photo_thumbs/`。Android 9 以下は WRITE_EXTERNAL_STORAGE（maxSdk 28、既存）を撮る前に求める。
- 他のアプリで撮った写真: ドライブの詳細の［この時間に撮った写真を追加］→ Photo Picker（権限不要、最大 50 枚）。EXIF の撮影日時が
  ドライブの前後 10 分に入るものだけ、位置は EXIF の GPS → 軌跡から補間。同じ URI・同じ時刻（±1 秒）は重複として飛ばす。駐車の区間に入るものは駐車に紐づける。
- 表示: ドライブの詳細の地図に縮小版のマーカー（タップで拡大・左右に送る）、概要に写真の列、タイムライン（§5.2）、まとめの全走行の地図（切り替え）。
  削除は「アプリから外す」（紐づけと縮小版だけ）か、アプリで撮った写真なら「ライブラリからも削除」（Android 11+ は `createDeleteRequest` の確認）。
  ドライブを消すと紐づけ（photo の行、CASCADE）と縮小版が消える（写真の本体は残る）。
- GPX: 設定「GPX に写真・駐車の位置を入れる」（既定 ON）で、位置の分かる写真を wpt（名前「写真 HH:mm」、type = photo、sym Scenic Area）。
- バックアップ（ZIP）には写真の紐づけを入れない（自転車ルートロガーと同じ。写真の本体はフォトライブラリにあるので、端末を移すときは写真アプリの方で移す）。

### 3.10 表示は「あとから重ねる」・横向きの録画（0.4.0〜、2026-10-13 ユーザー要望「ドラレコは横画面で撮るのが普通。地図など隠す場合、黒くするのではなくて、表示から消して」）

- **録画の向き**（設定、既定 横）: 録画 ON の間は画面を横に固定し、横長（16:9）で録る（§3.1）。走行画面は横向きの配置（速度・時刻・メーターは左と上、
  ［保護］［録画 OFF］［駐車する］［終了］は右端に縦、地図の小窓はその左下、［写真］はその上）。記録だけ・駐車中の画面は縦横どちらでも。
- **表示の入れ方**（設定「表示の入れ方」、既定「あとから重ねる」）:
  - **あとから重ねる**（既定）: 録画は**表示の無いきれいな映像**で保存する（OverlayEffect を結ばない。clip の `laterOverlay = 1`）。
    日時・速度・緯度経度・方位・メーター・地図・アプリ名は、**再生・書き出しのときに GPS の記録（時刻つき）から描いて重ねる**:
    - 描く部品は録画の焼き込みと同じ（`BurnInRenderer`＝`BurnInText`・`GaugeRenderer`・`MapBurnRenderer`）なので見た目がそろう。
    - 書き出し（SNS 用・ギャラリー）: Media3 Transformer の `OverlayEffect` に `LaterOverlay`（BitmapOverlay）。フレームの時刻 → 壁時計
      （動画の開始＋切り出しの頭＋出力の時刻）→ `TrackSync` でその時刻の位置・速度・方位を補間（`LaterOverlayPlan`、純ロジック・単体テスト LaterOverlayTest）。
      重いので 200 ms ごとに描き直す（速度を隠す・出すが切り替わったらすぐ）。**切り抜き・縮小（Presentation）の後**に重ねるので、縦 9:16 に切り抜いても表示は出力の画面に収まる。
    - **入れない項目は最初から描かない**（覆いも残らない）。書き出しの画面で項目（日時・速度・方位・緯度経度・地図・アプリ名）を選ぶ（既定は設定の「表示」の項目）。
      「速度を隠す」は、しきい値を超えた時間帯（§5.1 の `SpeedHide` と同じ）だけ**速度の文字・速度計を描かない**（`SpeedDraw.OMIT`。配置はそのままなので他の表示は動かない）。
      設定で「---」を出す方式（`DASHES`）も選べる。**低い数字を出すことはしない。** 地図・緯度経度を隠す＝項目を外す（描かない）。
    - 地図のタイル: 書き出しの前に、走った範囲（120 か所まで間引いた点のまわり）のタイルをキャッシュ優先でそろえる（`GsiTileStore.warmAlong`、最大 20 秒。
      取得は地理院の作法どおり＝今までと同じ間隔・上限。地図を入れる設定（通信の同意）が OFF なら地図の項目は選べない）。
    - G は走行の記録に残していないので、あとから重ねる方式では描けない（焼き込み方式だけ）。
    - アプリ内の再生: 動画の上に Compose の Canvas で同じ描画を重ねる（動画が収まる矩形に、動画の大きさで描いて縮める）。［表示を重ねる］で外せる。
    - **ギャラリーへの書き出しも既定で表示を重ねる**（設定「ギャラリーに書き出すとき表示を重ねる」）。再生画面の［ギャラリーに書き出す］で
      ［表示を重ねて保存］［表示なしで保存］を選ぶ。重ねるときは元の解像度・ビットレート（4 Mbps 以上）で Transformer に通してから `Movies/ドライブロガー` に保存する。
      保護した動画を自動でギャラリーに出す機能は無い。
  - **録画のときに焼き込む**（旧方式。設定で選べる）: 0.3.0 までと同じ（§3.3）。この方式の動画と 0.3.0 以前に焼き込んで録った動画は、
    SNS 用に書き出すとき今までどおり**覆う方式**になる（画面に注意を出す）。`burnLayout` はそのために残す。
  - 焼き込んでいない動画（0.3.0 以前に焼き込み OFF で録ったものも）は、どれもあとから重ねられる（`!burnIn`）。
- エミュレータでの確認（2026-10-13）: 横で録画（1280×720、`laterOverlay = 1`、元のフレームに表示なし）→ SNS 用に全部入りで書き出し（速度計・コンパス・日時・緯度経度・
  地理院の地図と出典。86 km/h の場面は速度計だけが無い）→ 速度と地図を外して書き出し（速度計・地図の窓がどちらも無く、帯も残らない。コンパスが左下に詰まる）。
  `captures/v040/frames/`。

### 3.11 長時間録画（0.7.0〜、Room 版 5。2026-10-13 ユーザー要望「ドライブの録画ですが、ループ録画だけでなく長時間録画もしたい」）

- **録画の方式**（`dashcam/RecordMode`）: ループ録画（ドラレコ。0.6.0 までと同じ）/ 長時間録画（消さない）。動画ログと動画ファイルに方式を残す
  （`drive_log.recordMode`・`clip.recordMode`。0 = ループ / 1 = 長時間。Migration(4,5) で既存はループ）。
- **選び方**: 設定「録画の方式（既定）」（既定 ループ）。走行画面の［録画］の上に小さな切替「⇄ 方式 ループ / 長時間」（録画していない間だけ。押すたびに切り替え。
  長時間は赤い地）。この切替はその回だけ（`DriveController.nextVideoMode`。ドライブを開く・再開する・起動して読み込むとき設定の既定に戻す）。ホームの［記録＋録画］は既定の方式
  （カードの説明も方式に合わせる）。**録画中は方式を変えない**（止めて始め直す）。熱で止めて冷めたら同じ方式で再開（`videoMode`）。
  走行中の操作を増やさないため、方式のダイアログは長時間録画を始めるときだけ（ループは今までどおり 1 タップ。初回だけ熱の注意）。
- **開始の確認**（長時間録画のときは毎回。`ui/StartDrive`）: 端末の空き・画質と fps・およその録れる時間（（空き − 1 GB）÷ 1 時間の見積もり＝ビットレート × 1.1）・
  電源につなぐ・熱（熱くなりすぎると録画だけ止めて冷めたら再開）・自動では消さない（動画の一覧で整理）・ナンバーが写る。［長時間録画を始める］［ループ録画にする］［キャンセル］。
  空きが 1 GB＋5 分ぶん無ければ［長時間録画を始める］を出さない。
- **分割**: 設定「長時間録画のファイルの長さ」10 / 15 / 30 分（既定 10 分。debug だけ 1 分）。落ちたとき（CameraX の mp4 は仕上がらないと読めないことがある）に失うのを
  1 ファイル分に抑えるため。分割の仕組みはループと同じ（stop → すぐ次の start）。
- **消さない**: `LoopStoragePolicy` は `StoredClip.longRec` を数えない・消さない（§3.4）。長時間録画の間はループの容量の判定もしない（ほかの動画を消して空きを作ることはしない）。
  保護は無い（［保護］ボタン・通知の［保護］を出さない。衝撃は出来事 impact だけ）。
- **空き容量**（`LongRecordingPolicy`、純ロジック・単体テスト LongRecordingTest）: ファイルを始めるたびと 30 秒ごとに端末の空きを見て、**1 GB 未満で録画だけ止める**
  （StopReason.STORAGE_FULL → 出来事 storage_full・通知「空きが 1 GB を切ったので長時間録画を止めました」・走行画面の知らせ 15 秒。GPS 記録は続ける）。
  4K 60fps でも 30 秒で約 200 MB なので 1 GB の余裕の中で止まる。残りが 30 分未満なら帯「空きが少なくなっています（残り約 n 分）」。
  HUD は「REC（いまのファイル）・長時間（この録画の長さ）・この録画の大きさ・空き（約 n 時間）」（横向きは 1 行に詰める）。
- **再生・書き出しはつなぐ**: `ClipChain`（§5.1）は長時間録画なら同じ動画ログの続きのファイルを本数の制限なしでつなぐ（ループと長時間・別の録画はつながない）。
  再生画面は ExoPlayer のプレイリスト（`ClipChain.forPlayback`。ループは今までどおりそのファイルだけ）で、いまのファイルの開始時刻＋再生位置で GPS と同期、「ファイル i / n（全体の長さ）」。
  SNS 用の書き出しの［つなげる］も全部の続き。
- **管理**（`ui/ClipScreens`）: 動画の一覧に「長時間録画 n 回・m ファイル・合計（容量の上限・自動削除の対象外）」と絞り込み［長時間録画］。絞り込むと録画 1 回ごとのカード
  （開始〜終了・長さ・ファイル数・大きさ・［再生］［ギャラリーへ］［削除］）。ギャラリーへは［ファイルのまま保存（n 本）］（表示なし・そのまま写す・速い）か
  ［表示を重ねて 1 本に］（Transformer でつないで表示を重ねる。元のビットレート）。端末の空きを先に確かめる（そのままは合計＋200 MB、重ねるのは作る分と写す分で 2 倍＋200 MB）。
  再生画面の［削除］は「このファイルだけ / この長時間録画を全部」。各行・詳細の記録一覧に「ループ / 長時間」（「録画 2（長時間）」）。
- エミュレータでの確認は CLAUDE.md。

### 3.4 容量の管理（`LoopStoragePolicy`、純ロジック・単体テスト）

- 上限 L（2 / 4 / 8 / 16 / 32 GB、既定 8 GB）と、保護の上限 P（1 / 2 / 4 / 8 GB、既定 2 GB）。
- 通常（保護していない）ファイルに使える量 = L − min(保護の合計, P)。次のファイルの見積もり（ビットレート × 分割の長さ × 1.1）を
  足して超えるなら、**保護されていない古いファイルから**消す。録画中のファイルは消さない。**保護したファイルは消さない。**
- 保護の合計が P を超えても保護はする（衝撃のときに守れないのは困るため）が、警告を出す（P を超えた分は L の外にはみ出す）。
- 端末の空きが「次のファイル＋1 GB」を下回るときも古い通常ファイルから消す。消せる物が無く、次のファイルも入らないなら録画を止める
  （GPS 記録は続ける）。空きが少ないときは HUD と通知で警告。
- 判定はファイルを始めるたびと、30 秒ごと。
- 0.7.0〜 **長時間録画のファイル（`clip.recordMode = 1`）は数に入れない**: L・保護の合計・消す候補のどれにも入れない（§3.11）。端末の空きにだけは効く
  （実際に場所を取るので、空きが足りなければループのファイルは消える。長時間録画は消さない）。

### 3.5 保護（`ProtectionPlanner` / `ImpactDetector`、純ロジック・単体テスト）

- **録画中だけ**: ［保護］ボタン（走行画面の大きなボタン・通知の操作）と衝撃の検知で、**今のファイルと 1 つ前**、
  今のファイルの残りが 30 秒未満なら**次のファイルも**保護する（前後それぞれ 30 秒以上を残す）。
- 衝撃: `TYPE_ACCELEROMETER` から重力（指数移動平均）を引いた大きさ [G]。感度 高 1.2 G / 中 1.8 G / 低 2.5 G / OFF（既定 中）。
  開始から 3 秒は数えない（重力の推定が落ち着くまで）。一度検知したら 10 秒は次を検知しない（連続の抑制）。
- **0.8.0〜（自転車で段差の振動を衝撃と誤検知していた）**: 0.7.0 は 1 サンプル（20 ms）でもしきい値を超えれば衝撃だった。
  (1) しきい値以上が**続いた時間**で判定（車 40 ms・自転車 60 ms＝50 Hz で 3〜4 サンプル。段差・小石のトゲは 1〜2 サンプル、衝突・急停止は 50〜150 ms 続く）、
  (2) 直近約 2 秒の**揺れの RMS × 2** をしきい値に足す（荒れた路面・自転車では上がる。1 サンプルは 1 G で頭打ち・しきい値を超えている間は入れない）、
  (3) 大きく揺れている間（0.8 G 超）は重力の推定をほぼ止める（衝撃が重力に吸われて小さく見えないよう）、
  (4) 設定「乗り物」（§4.8）: 自転車はしきい値 1.6 倍、徒歩は検知しない。
  単体テスト（ImpactDetectorTest）: 自転車の荒れた路面 60 秒（振動 0.4 G＋1% の 2.5〜3.5 G のトゲ）で 0.7.0 の数え方は 5 回 → 0 回、4.5 G・120 ms は検知。
  車の穴（3 G・20 ms）は数えず、2.5 G・80 ms は検知。
- 保護はドライブの出来事（`trip_event`、type `impact` / `protect`、時刻・位置・G）にも残す。
  記録だけのときも衝撃は監視し、出来事 `impact` として残すだけ（保護する動画が無い）。［保護］ボタンは録画中だけ出す。
- 保護したファイルは一覧で印。動画の一覧で［保護を外す］と通常のファイルに戻る（次の容量の判定で古ければ消える）。

### 3.6 サービス（`DriveService`）

- **0.6.0〜 何かを記録している間（GPS ログ・録画・駐車中の徒歩の軌跡）だけ動く**。開いているドライブでも何も記録していなければ止まる（§4.6）。
  システムに再起動されたときは、記録中のまま落ちた GPS ログがあれば新しい GPS ログで続ける。以下は 0.5.0 までの説明（「開始」は GPS ログの開始と読み替える）。

- 開始はホームの［記録だけ］［記録＋録画］（アプリが前面にあるとき。0.4.1 までは走行画面の［開始］）。型は記録だけなら `location` のみ。
  録画 ON（前面のときだけ）で `startForeground` をし直して `camera`（| `microphone`：音声 ON・許可あり）を足し、
  録画 OFF で `location` だけに戻す。Android 14+ は camera / microphone 型を前面から足す必要があるため。
- 画面を消しても・ホームに戻っても続く（PARTIAL_WAKE_LOCK・最大 24 時間）。通知に［保護］［終了］。
- プロセスごと落ちてシステムが再起動したとき（START_STICKY・intent = null）: カメラは裏から開けないので録画はしない。
  位置の「常に許可」があれば GPS 記録だけ続け（出来事 `restarted`）、無ければ「止まりました」の通知。
  次にアプリを開くと（ホームの上に）「途中で終わったドライブ」として続けるか終えるかを聞く（自転車ルートロガーと同じ）。
- 熱（API 29+ `PowerManager.addThermalStatusListener`）: SEVERE 以上で録画だけ止め（GPS は続ける）、通知と出来事 `thermal`。
  MODERATE 以下に 60 秒戻ったら録画を再開。
- カメラを他のアプリに取られた（`CameraState` のエラー）: 出来事 `camera_lost` と通知。CameraX が開き直したら次のファイルから再開。
- 音声: 既定 OFF。ON にするときに RECORD_AUDIO を求め、「同乗者の会話も録音されます」の注意を出す。走行中は変えられない。

## 4. GPS 記録（record/・stats/）

自転車ルートロガーの RideTracker / RecordingSession / RideAnalysis をもとに車向けにした。

- `DriveTracker`: 跳びの除去 250 km/h、精度 30 m 超は捨てる、距離は 5 m 以上動いたらまとめて足す、止まっている＝5 km/h 未満。
  **自動一時停止は既定 OFF**（信号待ちも走行時間に入れる）。ON のときは 60 秒止まったら一時停止。
  OFF でも「停車時間」（5 km/h 未満だった時間）を数え、詳細に「停車を除いた平均」を出す。
  進行方向（`courseDeg`）: 端末の方位が無い（エミュレータの geo fix など）ときは、10 m 以上離れた前の点からの方位。
- 点は採用するたびに Room へ（1 本のキュー）。落ちても点は残り、続きから記録できる。
- 詳細: 大きな地図（速度で色分け: 〜20 / 20–40 / 40–60 / 60–80 / 80–100 / 100+ km/h）・統計・区間（5 km / 10 km ごと）・
  速度の分布（10 km/h ごと）・出来事（保護・衝撃・GPS 不通・熱など）・そのドライブの動画。GPX 書き出し・共有。

### 4.2 GPS と加速度・ジャイロの融合（record/GpsImuFusion。0.3.0〜、2026-10-13 ユーザー要望「GPS の精度が低めなので加速度センサとカップリングして精度を上げたい」）

- 設定「GPS を加速度・ジャイロで補正する」（既定 ON）。拡張カルマンフィルタ（純ロジック・単体テスト FusionTest）。
  - 状態: 局所平面（最初の点が原点。20 km 離れたら原点を置き直す）の位置 x（東）・y（北）、速さ v、進行方向 θ。
  - 予測（加速度のたび、約 50 Hz・最大 0.1 秒刻み）: 位置 += v·(sin θ, cos θ)·dt、v += 前後の加速度·dt、θ += ヨーレート·dt。
    前後の加速度は `VehicleGEstimator` が車の向きにそろえたもの（そろうまでは無し＝雑音を大きく見る）。ヨーレートはジャイロを重力の向き（上）に
    射影した回転（左回りが正なので符号を反転）。停車中にジャイロのずれ（バイアス）を少しずつ求めて引く。
  - 更新（GPS のたび）: 位置（精度 × 0.75 を σ、最低 2.5 m）・速さ（σ 0.6 m/s。端末の速度が 0 なのに位置が動いている＝エミュレータの geo fix などは、
    位置の差からの速さをゆるく使う）・方位（3 m/s 以上のときだけ、σ 12°）。向きが分からないうちは、動いた向き（15 m 以上）から決める。
  - 外れ値: マハラノビス距離² > 25 の位置は捨てる（向きが分かっているときだけ）。4 回続いたら GPS に合わせ直す。停車の後の最初の測位は外れ値にしない。
  - GPS が来ない間（1.5 秒以上）: 1 秒ごとに推測の点（推測航法、`source = 2`）を記録。加速度が使えれば 30 秒、使えなければ 8 秒、または誤差（1σ）が 60 m を
    超えたら打ち切る（次の GPS からやり直す）。
- 記録: `trip_point` の lat/lon/speed は融合後（統計・地図・同期・GPX の既定はこちら）。元の測位は `rawLat/rawLon/rawAccuracy/rawSpeed` に残す
  （`source` = 0 GPS のまま / 1 融合 / 2 推測航法 / 3 停車中）。GPX の書き出しは設定で「元の GPS の値」も選べる（推測・停車中の点は除く）。
- 単体テストの合成データ（雑音 5 m の GPS 1 Hz＋雑音とずれ入りの加速度・ヨーレート）: 位置の RMS 誤差 GPS 単独 7.3 m → 融合 2.9 m、
  速さ 0.56 → 0.39 m/s、GPS が 15 秒欠けても最大 15 m、60 秒欠けると 30 秒で打ち切り。
- **限界（正直に）**: スマホの加速度センサーは雑音とずれ（バイアス・温度変化）が大きく、ホルダーの揺れも拾う。向きの補正（前後・左右）が
  そろうまでは加速度を使えない。推測航法は数十秒で数十 m ずれるので長いトンネルは補えない（打ち切って GPS の再取得を待つ）。
  端末を付け直すと向きの補正がそろい直すまでずれる。GPS 自体が大きく外れる（ビルの反射）ときは、外れ値として捨てきれずに引っ張られることがある。
  実機でのチューニング（雑音の値）は未実施（エミュレータは加速度が一定・ジャイロ 0 のため）。
- **0.8.0〜**: 歩いている間・Google の融合測位・乗り物が自転車/徒歩のときは使わない（§4.7・§4.8）。向きが分からない間（7 km/h 未満）の
  位置の広がりを「速さ × 時間」で増やす（刻みの二乗の和では小さすぎ、低速で GPS に約 10 m 遅れていた。合成データ 1.5 m/s で RMS 9.9 → 4.5 m）。

### 4.3 停車中は測位を止める（service/DriveService・record/StopDetector。0.3.0〜、同じ要望「停車時には測位を停めたい。データとしては同じ位置に居るとします」）

- 設定「停車中は測位を止める」（既定 ON）。`StopDetector`（純ロジック・単体テスト）: 直近 2 秒の重力を除いた加速度の平均 < 0.25 m/s²（最大 < 0.75）、
  ジャイロ < 0.06 rad/s、記録の速さ < 0.8 m/s の状態が 4 秒続いたら**停車**。動き出してから 15 秒は停車にしない。
- 停車: `LocationHub.setPaused(true)` で GPS の更新を外す（画面が取っていても止める）。停車を始めた位置を保ち、2 秒ごとに**同じ位置・速さ 0 の点**
  （`source = 3`）を記録する → 距離は増えず、停車時間に入る。焼き込み・画面の速度は 0 km/h、位置は停車の位置。通知は「停車中・測位を止めています」、
  画面の GPS の表示は「停車中（GPS 停止）」。GPS 不通の出来事にはしない。
- 動き出し: 直近 0.4 秒の加速度の平均 ≥ 0.6 m/s² またはジャイロ ≥ 0.2 rad/s で**すぐ**再開。融合は停車の位置・速さ 0 から始める（再開直後は停車の位置からの移動）。
  加速度で拾えないゆっくりした動き出しに備えて、停車中も 2 分ごとに 20 秒だけ GPS を点け、停車の位置から 30 m 以上（または 2 m/s 以上）動いていたら再開する。
- 限界: 加速度センサーが無い端末では停車にしない。振動の大きい車（ディーゼルのアイドリング）は「静か」にならず停車にしないことがある（しきい値は実機で要確認）。

### 4.4 駐車・寄り道（record/DriveSession・service/DriveService・ui/DriveScreen の ParkedScreen。0.4.0〜、2026-10-13 ユーザー要望「ドライブという記録にして、途中 GPS の記録を止めて、駐車して徒歩で歩いて写真撮影という使い方」）

- 走行画面の［駐車する］（停車中＝5 km/h 未満か速さが分からないときだけ押せる。確認あり）: 録画中なら録画を止め、**走行の GPS 記録を止める**（ドライブは終わらない）。
  駐車した位置（最後の走行の点）を `park` 表に残す（開始・終了・位置・徒歩の距離。地図に P の印）。走行の区間はここで切る（`DriveTracker.breakSegment`）。
  サービスは `LocationHub.setPaused(true)` で測位を止め、停車の判定・衝撃の監視（歩く揺れ）・GPS 不通の判定をしない。通知は「駐車中」。
- 駐車中の画面: 経過時間・［現在地を測る（1 回）］（`LocationHub.oneShot`: 最大 8 秒、精度 30 m 以内が来たらすぐ、100 m 以内の一番よい位置）で
  車までの距離と方角（常時の測位はしない）・この駐車の写真の数・［写真を撮る］［ドライブを再開］［ドライブを終える］。地図に P・測った現在地・この駐車の写真。
- 駐車中の写真: アプリ内カメラで撮る。撮るたびに 1 回だけ測位して写真の位置にする（取れなければ位置なし。走行の軌跡からは補間しない）。`photo.parkId` に紐づく。
- 徒歩の軌跡（設定「駐車中の徒歩の軌跡も記録する」、既定 OFF）: ON なら駐車中も 5 秒ごとに測位し、精度 50 m 以内・前の点から 10 m 以上動いた点を
  `walk_point` に残す。距離は `park.walkDistanceM`（走行距離とは別）。地図では紫の点線。GPX の書き出しでは 2 本目の trk（駐車ごとに trkseg）。
- ［ドライブを再開］: 駐車を閉じて走行の記録を続ける（次の点から新しい区間＝地図の軌跡は駐車の前後で切れる、GPX の trkseg も分かれる）。何度でも駐車→再開できる。
- 統計: 走行距離・走行時間には駐車中を含めない（区間をまたぐ距離・時間は数えない。単体テスト TimelineTest.parkThenResumeDoesNotAddDistance）。経過時間は含む。
  ドライブの詳細とまとめに「駐車の回数・駐車時間の合計・写真の数」（と徒歩の距離）。
- 落ちたとき: 駐車中に落ちて続けたら駐車中のまま続ける。「終了して保存」なら終わっていない駐車を閉じる。
- バックアップ: 駐車の区間は manifest に入れる（徒歩の点と写真の紐づけは入れない）。
- エミュレータでの確認: 1.91 km 走って駐車 → 2 分 11 秒歩いて写真 2 枚（駐車の位置から 50〜60 m の位置）→ 再開して 0.4 km → 終了。
  距離 2.29 km（駐車の間は増えない）、走行時間 4:07・経過時間 6:25、区間 2 つ。タイムラインで駐車の下に写真 2 枚が入れ子。

### 4.6 ドライブ＝GPS ログ・動画ログの入れ物（0.6.0〜、Room 版 4。2026-10-13 ユーザー要望「ドライブは GPS ログ・動画ログの一つ上の概念で、ドライブの開始＝記録の開始ではない。ドライブの中で複数の GPS ログ・動画ログを記録できるようにして。また、ドライブを終了しても、再開して記録を追加できるようにして」）

- **データ**（`data/Entities.kt`）:
  - ドライブ `trip`: 名前・作成（startedAt）・最後の記録（endedAt）・最終更新（updatedAt）・状態 status（0 = 開いている / 2 = 閉じた）・統計（全 GPS ログの合計のキャッシュ）。
  - ログ `drive_log`: kind 0 = **GPS ログ**（［GPS 記録］〜［GPS 停止］。点は `trip_point.logId`。距離・走行時間・停車時間・最高速度・点の数はこのログの点だけで計算）、
    kind 1 = **動画ログ**（［録画］〜［録画 停止］。中身はループ録画のファイル群＝`clip.logId`）。endedAt = null は記録中。
  - 写真・駐車・出来事（保護・衝撃・GPS 不通…）はドライブに属する（時刻で並ぶ）。0.5.0 までの出来事 `video`（録画した時間帯）は動画ログになった
    （地図の「録画した区間」・タイムライン・まとめの録画した時間は、動画ログを同じ形の出来事にして今までの処理で扱う `TripRepository.videoEvents`）。
  - 駐車（§4.4）は「GPS ログを閉じて駐車の位置を記録する」特別な形。［走行を再開］で駐車を閉じ、GPS を記録していたときの駐車なら新しい GPS ログを始める。
- **集計**（`TripRepository.replay`・`segmentsOf`）: 点は区間（segment）とログ（logId）が変わるところで切る＝**ログとログの間は距離・時間に入れず、地図の線もつながない**。
  ドライブの距離・走行時間・最高/平均・区間・速度分布・開拓したマス・まとめは全 GPS ログの合計。経過時間（ドライブを作ってから最後の記録まで。開いている間は今まで）と
  走行時間（GPS ログの合計）を分けて出す。新しい GPS ログは必ず新しい区間の番号から。点が 1 つも無い GPS ログは止めたとき・閉じたときに消す。
- **セッション**（`record/DriveSession`、アプリに 1 つ）: 開いているドライブ（create / restore / close）と、その中の GPS ログ（startGpsLog / stopGpsLog）・動画ログ（startVideoLog / endVideoLog）。
  ドライブ全体の DriveTracker を 1 つ持ち、GPS ログの境目で breakSegment（ドライブの合計がそのまま出る）。ログの統計は閉じるとき DB の点から流し直す。
- **サービス**（§3.6）: **何かを記録している間だけ**（GPS ログ・録画・駐車中の徒歩の軌跡）。型は GPS＝location、録画＝location|camera(|microphone)。
  記録が無くなったら自分で止まる。何も記録していない開いたドライブではサービス・通知なし（画面が見えている間だけ地図の現在地のために測位）。
  通知の操作は［保護］（録画中）［記録を停止］（ドライブは開いたまま）［ドライブを終了］。
- **録画には GPS ログが要る**（表示はあとから GPS の記録から重ねる §3.10）: ［録画］で GPS ログが止まっていれば先に始めて「録画のため GPS 記録も始めました」。
  ［録画 停止］では GPS ログは続ける。録画中の［GPS 停止］は確認して両方止める。
- **開く・閉じる・再開**（`service/DriveController`）:
  - ホーム「ドライブを始める」: ［GPS 記録から］［記録＋録画］（大きな 2 択。前回の選択＝設定「開始時の既定」）と［記録せずに始める］（地図と現在地だけ）。
    記録しないで開くときも位置の権限は聞く（断られても開く）。
  - ［ドライブを終了］で閉じる（記録中のログ・駐車・続いている出来事を閉じ、統計を計算し直す。ログ・写真・駐車がどれも無ければ保存しない）。
  - ［このドライブを再開］（詳細・一覧・ホームの最近のドライブ）: status を 0 に戻してセッションに読み込む（点を流し直して合計から続ける）→ 走行画面。
    **開いているドライブは同時に 1 本まで**: 別のが開いていれば「『A』を終了して『B』を再開します」の確認。
  - 起動時（`DriveApp`）に開いているドライブを DB から読み込む。記録中・駐車中に開いたときだけ走行画面へ直接（何も記録していなければホームの「ドライブ中です」のカードから戻る）。
- **落ちたとき**: 記録中のまま（endedAt = null）のログは、次に読み込むとき GPS ログは最後の点・動画ログは最後のファイルの終わりで閉じ、
  「途中で終わった記録があります」（［GPS 記録を続ける］＝新しい GPS ログ・出来事 interrupted /［ドライブを終了］/［止めたまま］）。
  システムがサービスを再起動したとき（START_STICKY）は「常に許可」があれば新しい GPS ログで自動で続ける（出来事 restarted。カメラは裏から開けないので録画はしない）。
- **詳細**（`ui/TripScreens`・`ui/LogUi`）: 概要に「記録（GPS ログ n 本・動画ログ m 本）」の一覧（時刻・長さ・距離・走行時間・平均／動画の本数と大きさ。動画ログはタップで再生）。
  各ログのメニュー: GPS ログは［このログを GPX で書き出す］［このログの GPX を共有］（`drive_…_gpsN.gpx`、trk 名に「GPS N」。写真・出来事はログの時間帯のものだけ）、
  ［このログを削除］（GPS は点ごと消してドライブの統計を計算し直す・動画はファイルも消す。記録中のログ・記録中のドライブのログは消せない）。
  ドライブ全体の GPX はログ・区間ごとの trkseg。タイムラインに「GPS 記録 n」（開始〜終了・距離）と「録画 n」。
- **まとめ**: 閉じたドライブだけ。曜日・時間帯は GPS ログの時間帯で数える（再開して日をまたいだドライブの、記録していない時間を入れない `TripFacts.logSpans`）。
- **移行**（Room 3 → 4。`AppDatabase.MIGRATION_3_4_SQL` ＋ `LogMigration.run`）: 既存のドライブは「閉じたドライブ＋駐車で分かれた GPS ログ＋録画した区間ごとの動画ログ」。
  点（id の順）を駐車の開始時刻で分け、ログの統計は流し直して計算。動画は録画した区間（頭は 15 秒・終わりは 5 秒の余裕、無ければいちばん近い区間）の動画ログへ。
  記録中のまま落ちたドライブ（status 0）は開いたまま、最後の GPS ログ（駐車中でなければ）と終わっていない動画ログは記録中のまま → 次に開いたとき上の「途中で終わった記録」。
  SQL とデータの処理は `SqlRunner` 越しなので、単体テスト（MigrationTest）が sqlite-jdbc で同じ処理を流してスキーマ v4 と突き合わせる。
- **バックアップ**: manifest に GPS ログの区間（`gpsLogs`）、動画ログは出来事 video として入れる（0.5.0 までの形）。読み込むと点を GPS ログに分け、video は動画ログにする。
  `gpsLogs` の無い古いバックアップは駐車で分ける。

### 4.7 徒歩では融合をやめる・Google の融合測位・獲得標高・生の GPS の比較表示（0.8.0〜、Room 版 6。2026-10-13 ユーザー報告）

報告: Pixel で徒歩で記録したら、まとめの地図の軌跡が数十 m 規模の直線と鋭い角のジグザグになった（駅の近く）。獲得標高 671 m（平地）。
GnssLogger の FLP/WLS を見せて「高精度測位モードはあるか」。

- **原因の調査**（単体テスト WalkFusionTest。合成データ `WalkSim`: 1.35 m/s で歩く・ポケットで歩くたびに ±25° 振れる・途中で 60° 傾き直す・手に持つ、
  加速度（重力＋上下 2.0・前後 1.2 m/s² の 1.8 Hz）・ジャイロ 50 Hz、GPS 1 Hz（ゆっくりしたずれ σ 3 m＋白色 1.5 m）を、ImpactMonitor → 融合 → DriveTracker・停車の判定と同じ順に流す）:
  - **重力が「前後の加速度」に漏れる**: `VehicleGEstimator` は走っている間の重力の推定を約 100 秒かけてゆっくり追う（車のホルダーなら向きは変わらない）。
    歩くと端末の向きが変わるので、重力の向きのずれがそのまま水平の加速度になり、GPS の速度の変化と偶然そろったものから「前」が決まってしまう
    （前後の加速度が使える＝補正済みの時間 22〜64%、その値は最大 9.4〜11 m/s²＝ほぼ 1 G）。
  - **推測航法が飛ぶ**: その加速度で速さの推定が暴れ、GPS が 3〜4 秒欠けるだけで推測航法が直線に 100〜170 m 飛ぶ（推測の点を記録する）→ 次の GPS は外れ値として
    捨てられ、4 回続いて合わせ直す（引き戻し）。＝「直線と鋭い角のジグザグ」。位置の RMS 誤差は欠けありで 生の GPS 4.7〜5.6 m → 記録 12.5〜17 m（最大 107〜168 m）。
  - **低速での遅れ**: 7 km/h 未満では向きが分からず、位置が「動かない」予測になり GPS に約 10 m 遅れていた（欠けなしでも記録の RMS が生の GPS の 1.4〜1.7 倍）。
  - 停車の判定: 歩いている間は揺れが大きく停車にならない（停車 0 回）。止まって立っているときだけ停車になる（正しい動き）。
  - 点の記録: 1 秒ごとの測位をすべて保存（精度 30 m 超・250 km/h 超の跳び・同じ時刻だけ捨てる。距離や時間の間引きはなし）。詳細の地図は 8000 点まで間引くだけ、
    まとめの細かい線は 8 m の Douglas–Peucker。ジグザグは記録そのもの。
- **徒歩では融合をやめる**（`record/WalkDetector`・`record/FixPipeline`。純ロジック）:
  - 歩行の判定: 加速度の大きさ |a|（重力を含む＝向きによらない）を 50 Hz にそろえ、直近 4 秒（2 秒たまったら判定）の標準偏差 ≥ 0.6 m/s² かつ 1 歩の周期（0.33〜0.9 秒）の
    自己相関 ≥ 0.5 が「周期的な揺れ」。揺れが 3 秒続き GPS の速さ 10 km/h 未満（分からなければ可）で**徒歩**。15 km/h 以上が 3 秒、または揺れなしで 10 km/h 以上が 10 秒で徒歩をやめる。
    信号待ちで止まっても徒歩のまま。合成データで歩き始めから 5 秒で徒歩、車（ホルダー・道路の振動）は 12 m/s・1.5 m/s とも徒歩にならない。
  - `FixPipeline` の 4 つの方式: FUSED（車。今までの融合）/ WALK（測位のまま・推測航法なし）/ RAW（融合 OFF）/ EXTERNAL（Google の融合測位）。融合から外れたら融合の状態を捨て、
    戻ったら次の GPS からやり直す。合成データの徒歩で記録 = 生の GPS（RMS 4.6〜5.6 m、推測航法 0 点、停車 0 回）。
  - 駐車中の徒歩の軌跡（§4.4）はもともと融合していない（測位のまま `walk_point`）。
  - 走行画面の GPS の表示: 「GPS · 徒歩（補正なし）」「GPS · Google の融合測位」。
- **Google の融合測位**（設定「測位の方式」= 端末の GPS（既定）/ Google の融合測位（高精度）。`sensor/LocationHub`）:
  `FusedLocationProviderClient` + `PRIORITY_HIGH_ACCURACY`・1 秒。`GoogleApiAvailability` が SUCCESS でなければ端末の GPS。要求が失敗したら端末の GPS に戻す。
  FLP の位置（provider = fused）には**自前の融合をかけない**（FLP がセンサーと融合済み。二重にすると遅れ・暴れが重なる）。停車で止める・停車中の確かめは同じ。
  駐車中の 1 回の測位（`oneShot`）は LocationManager のまま。**既定は端末の GPS**（徒歩は融合をやめるだけで生の GPS と同じになるため。FLP の実機での効き目は未確認。
  FLP を既定にするとプライバシーポリシー上の通信先も増える）。play-services-location 21.3.0 を追加。
- **点に足した列**（Room 6）: `trip_point.altAccuracy`（verticalAccuracyMeters）・`trip_point.provider`（0 不明 / 1 GPS / 2 ネットワーク / 3 融合測位）。`trip.vehicle`（§4.8）。
  Migration(5,6) は ALTER TABLE だけ（MigrationTest で v5→v6・v1→v6）。
- **獲得標高**（`stats/ElevationGain`。まとめ・ドライブの詳細で同じ計算。表示のたびに点から計算するので既存の記録もそのまま新しい数え方）:
  使う点 = 高度あり・GPS/融合の点（推測・停車中は除く）・ネットワーク位置でない・高度の精度 ≤ 15 m（無い古い点は水平の精度 ≤ 20 m）。
  前後 2 点の中央値 → 前後 60 秒かつ走った距離で前後 300 m の移動平均 → 直近の底から **10 m** 以上上がったときだけ数える（ヒステリシス）。
  合成データ（白色 σ 5 m＋ずれ σ 4 m・τ 60 s＋ときどき 30 m の跳び）: 平地 1 時間の徒歩で 10〜20 m（0.7.0 の数え方は 1200〜1400 m）、車 54 km/h で 30〜60 m、
  100 m の坂で 100〜110 m、車の 40 m の短い坂 4 回で 153〜163 m。ネットワーク位置の高度（基準が違って 0/80 m を行き来）で 0.7.0 は 10 分で 637 m → 0 m。
  エミュレータ: 0.7.0 で ±8 m の高度で 25 m → 0.8.0 で 0 m。
  - 0.7.0 の 671 m は、GPS の高度の雑音（指数移動平均 α 0.3 では数 m の揺れが残り、4 m の登りを何度も数える）と、GPS が 10 秒来ない間に混ざるネットワーク位置の高度が主因と見ている。
  - 限界: GPS の高度は水平より悪く、数分かけてゆっくり 10 m 前後ずれる。平地でも 1 時間で 10〜60 m 程度は出ることがある（目安と表示）。
- **生の GPS の比較表示**（ドライブの詳細の地図の［生の GPS の点を重ねる］）: 赤紫の細い線＝元の測位（融合した点は rawLat/rawLon、GPS のままの点はそのまま。推測・停車中の点は無し）。
  ズーム 16 以上で、見えている範囲の点（最大 400）と精度の円（accuracy の半径）。色の線（記録＝なめらかにした線 §4.8）と見比べられる。
  元の測位は 0.3.0 から保存しているので、既存の記録でも表示できる（精度 30 m 超などで捨てた測位は無い）。

### 4.8 軌跡のなめらかさ・乗り物（0.8.0〜。2026-10-13 追加要望「自転車で数 m〜10 m の小さな段差・ギザギザ。融合あり・なしどちらでも」「衝撃の検知が自転車だと非常に起きやすい」）

- **原因**: GPS の測位そのものの数 m のばらつき（1 秒ごとの点を全部つなぐので、自転車・徒歩の速さでは点の間隔とばらつきが同じくらいになり折れ線になる）。
  融合の有無とは関係ない（融合は車向けで、自転車ではほぼ GPS のまま）。距離もギザギザの分だけ長く出る（合成データ: 自転車 5 m/s で ×1.26〜1.30、徒歩で ×3.3）。
- **軌跡をなめらかにする**（設定、既定 ON。`geo/TrackSmoother`。純ロジック・単体テスト TrackSmootherTest）:
  等速モデル（位置・速度、東と北は別々）のカルマンフィルタで前から流し、**RTS スムーザ**で後ろから戻す（両方向）。観測の雑音 = 各点の精度 / 1.5（最低 1.5 m）＝精度の悪い点・
  推測航法の点は弱く効く。外れ値: 前に使った点から乗り物の上限（車 70・自転車 25・徒歩 8 m/s）を超えて跳んだ点・予測からマハラノビス距離² > 20 の点は使わない
  （その時刻は前後からの推定）。外れが 3 回続いたら外れ始めからやり直す（本当に動いた・測位し直した）。30 秒あいたら別の区間。
  加速度の雑音は乗り物ごと（車 2.0・自転車 1.2・徒歩 0.6 m/s²。大きいほど角に追従）。
  合成データ（白色 σ 2.5 m＋ずれ σ 1.5 m）: 直線で RMS 3.9 → 1.8〜2.6 m・線の長さ ×1.03〜3.4 → ×0.99〜1.04、L 字の交差点（車 8 m/s・半径 12 m、自転車 4 m/s・6 m、徒歩 1.4 m/s・2 m）で
  角の近くの最大のずれ 5.3〜7.5 → 2.5〜5.8 m（角を丸めすぎない）、円弧（半径 60 m）で 3.9 → 2.2〜2.4 m、80 m 飛んだ点は使わない（最大のずれ 83 → 7.4 m）。
  - 使うところ: ドライブの詳細の地図・区間・速度の分布、まとめの地図・速度の分布、SNS 用の画像、動画に重ねる地図・緯度経度（`displayPointsBetween`）、記録中の線、
    統計の**距離**（GPS ログを閉じる・ドライブを閉じるときに、なめらかにした点で DriveTracker を流し直す）。速度（ドップラー）・時間はそのまま。
  - **記録（DB の点）は変えない**。比較表示（§4.7）で元の測位と見比べられ、GPX は設定「GPX の書き出し」で なめらかにした位置（既定）/ 記録した位置（補正後）/ 元の GPS の値。
    0.7.0 までの「元の GPS の値」の設定は引き継ぐ。
  - 記録中の線は前向きだけのフィルタ（`TrackSmoother.Forward`。遅れ 1 m 未満）。記録中の距離（HUD）は今までどおり記録した点で、閉じたときになめらかにした点で計算し直す
    （少し短くなる。エミュレータの徒歩 0.13 → 0.10 km）。
  - 既存の記録: 起動時に「閉じたドライブの統計をどの点で計算したか」（SharedPreferences `state` の `stats_points`）が設定と違えば、閉じたドライブの GPS ログ・ドライブの統計を
    計算し直す（0.7.0 から上書きした最初の起動・設定を切り替えたとき）。地図などは表示のたびに計算するのでそのまま効く。エミュレータ: 0.7.0 の徒歩 0.22 km → 0.18 km。
- **乗り物**（設定、既定 車。`record/Vehicle`。新しいドライブと開いているドライブの `trip.vehicle` に入れる。詳細に「乗り物: 自転車」）:

### 5.1 SNS 用の書き出し（share/・ui/SnsExportScreen。0.3.0〜、2026-10-13 ユーザー要望）

要望「SNS にアップロード出来る機能、その際上限を超えた速度を下げる機能」→ 確認の結果「**決めた速度を超えた場面だけ速度の表示を隠す**」。
**実際より低い数字を出す（速度を偽る）ことはしない。** 元の動画と記録はそのまま。**アップロード（各 SNS にログインして投稿）はしない**:
書き出した動画を共有の画面（ACTION_SEND）で X・Instagram・YouTube・LINE などのアプリに渡す。

- 入口: 再生画面の［SNS 用に書き出す］、動画の一覧の各行のボタン。
- 範囲: RangeSlider と［開始＝再生位置］［終了＝再生位置］［範囲を再生］。前後に続けて録ったファイル（前の終わりから 5 秒以内・同じ大きさ、前後 3 本まで。
  `ClipChain`）を［つなげる］と、1 本の時間軸として切り出せる（Transformer の EditedMediaItemSequence）。
- プリセット（`SnsPreset`。上限は 2026-10 時点の目安）: X（2 分 20 秒・512 MB・1080p まで、8 Mbps）、Instagram リール（90 秒・1080p、縦 9:16 に切り抜きを選べる）、
  YouTube（制限なし・録画と同じ画質 12 Mbps@1080p）、LINE（5 分・720p・3 Mbps）、カスタム（解像度・ビットレート・切り抜き）。
  長さが上限を超えると書き出せない（［開始から上限の長さに合わせる］）。見積もり =（映像＋音声 128 kbps）× 長さ × 1.02 + 64 KB。
  大きさの上限を超えそうならビットレートを下げ、解像度ごとの最低（1080p 2.5 Mbps など）を下回るなら解像度を 1 段ずつ下げる。元の平均ビットレートより上げない（`ExportPlanner`）。
- **速度を隠す**（ON/OFF、しきい値 40〜120 km/h・5 km/h 刻み、既定 60）: `SpeedHide`（純ロジック）。GPS の点の隣り合う 2 点の間を、どちらかが
  しきい値を**超えて**いれば隠す（焼き込みは直前の点の値を出し続けるので、補間でなく両端の大きい方）。GPS が来ていない間も両端のどちらかが超えていれば隠す。
  1 点だけの山も隠す。前後に 1 秒の余裕（動画と GPS の時刻の差・焼き込みの遅れ）、1 秒以内の隙間はつなぐ。壁時計の時間帯を各ファイルの出力の時刻に変換（`ExportTimeline`）。
- 覆い方（`CoverOverlay`＝Media3 の BitmapOverlay、`CoverPlan`＝純ロジック）: フレームと同じ大きさの画像に、文字なら速度の枠を不透明な帯で覆って
  「--- km/h」、メーターなら速度計の円を不透明な円で覆って「---」（針と数字が消える）。方位などほかの項目はそのまま。
  緯度経度を隠す（常に、既定 ON）・地図を隠す（常に、既定 OFF）も同じ画像に描く。画像は隠す・隠さないが切り替わるときだけ描き直す（世代が変わったときだけ GPU に送られる）。
  効果の順: 覆い（切り抜き前の正立のフレーム。Transformer はデコーダーで回転を反映してから効果に渡す）→ Presentation（切り抜き・縮小）。
  タイムスタンプは、つないだ出力の時刻（前のファイルの長さを足したもの）で渡される（エミュレータで確認）。ファイルの中の時刻で来た場合も最初のフレームで見分ける。
- 配置: clip の `burnLayout`（§3.3）。0.2.0 以前の動画は無いので、今の焼き込みの設定から推定し（`estimated`）、画面に「ずれることがある」と出す。
  焼き込み無しの動画は隠すものが無い旨を出す。向きの違う配置は当てない（縦の動画に横の配置）。
- 書き出し: Media3 Transformer 1.5（H.264 + AAC、ビットレート指定、エンコーダーのフォールバック ON）。進捗とキャンセル。アプリに 1 つ（`SnsExporter`）なので画面を離れても続く。
  書き出し先 `getExternalFilesDir(MOVIES)/sns/DL_SNS_<開始>_<プリセット>.mp4`（新しい 5 本まで残す）。［共有］（FileProvider）・［ギャラリーに保存］
  （MediaStore `Movies/ドライブロガー/SNS`）・［書き出した動画を再生］。

  写真 → 拡大表示。停車・駐車・その他 → 地図をその場所へ（位置が無ければその時刻の軌跡の位置）。

## 6. 安全・プライバシー

- 初回と走行画面に「運転中は操作しない・画面を注視しない・端末をしっかり固定・視界を妨げない位置に」。
- 走行中（10 km/h 超）は走行画面から設定・一覧・ホームへ移れない（設定で外せる。戻るも効かない）。［保護］［終了］だけ使える。ホームを開いたままドライブ中に動いているときも、ホームの入口は使えない。
- 動画・位置は端末の中だけ。送信しない（通信は地図のタイル（Google・地図の焼き込み ON のときの地理院タイル）と更新の確認だけ）。他人・他車のナンバーが写ることへの注意。録音は既定 OFF。
- SNS 用に書き出した動画は、利用者が［共有］で選んだアプリに渡したとき・［ギャラリーに保存］したときだけ端末の外・ほかのアプリに出る（§5.1）。
- バックアップ（ZIP）はドライブだけ（GPX＋manifest。駐車の区間を含む）。動画・写真の紐づけ・徒歩の点は入れない。Android の自動バックアップ・端末移行から DB と動画を外す。
- 写真（0.4.0〜）: 端末のフォトライブラリ（Pictures/ドライブロガー）に保存。EXIF に撮影日時と（設定で）位置。アプリには写真の参照・縮小版だけ。Photo Picker で選んだ写真は読むだけ。
  SNS 用の画像は利用者が保存・共有したときだけ外に出る。
- 表示はあとから重ねる（0.4.0〜 既定）: **元の映像には日時・速度・位置・地図が入っていない**。重ねるのは再生・書き出しのときだけ（書き出しで項目を外せば描かない）。

## 8. 確認の手順（エミュレータ）

- `adb -s emulator-5554`（Pixel 実機には触らない）。位置は `adb emu geo fix <lon> <lat>` を 1 秒ごとに。
- 流れ: 記録だけで開始 → 途中で録画 ON → 録画 OFF → 記録が続いていること（FGS の型が location に戻る）→ 録画 ON → 終了。結果は CLAUDE.md。
- 衝撃は `adb emu sensor set acceleration 0:9.8:40` → `0:9.8:0` … `adb emu sensor set acceleration 0:9.8:0` で戻す。
- 分割は設定で 1 分に。容量の上限は debug ビルドだけ 50 MB / 100 MB を選べる（容量の削除を短時間で確かめるため）。
- 焼き込みはファイルを `adb pull` してフレームを抜き出す（ffmpeg が無ければ、debug だけの `--es extractFrame <ファイル名>` で
  アプリが MediaMetadataRetriever で cache に PNG を書く）。
